# TODO 02：优惠对比自动验收检查

2026-09-28 15:58（上海）已部署。此次只增加本地数据验收，不增加抖音请求、不提高并发、不生成未经核验的优惠结论。

## 实现

`GET /api/v3/runs/:id/acceptance` 按指定轮次读取已完成品牌的名称匹配候选，复用现有同券条件比较逻辑。查询通过同一条 SQL 取得任务统计及当前/上一轮商品、规则、门店证据，避免逐券查询过程中混入不同基线。

每分钟自动保存最近轮次的 `data/reports/<run-id>.acceptance.json`。文件包含扫描进度、候选数、证据覆盖、上一轮可比较数量、价格下降线索、缺口汇总和最多 20 个降价样本。历史轮次可通过接口单独核验。

扫描结束和优惠验收通过分开表示。当前严格品牌身份与完整权益尚未接通，验收结论保留 `not_accepted`，同条件返回字段相同也只是线索。
