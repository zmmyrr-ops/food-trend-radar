# 门店缺失后的尾批续采

## 问题与修复

旧逻辑在一批 20 个门店 ID 少返回一个时直接结束任务，后续已知 ID 不再查询。现继续执行剩余批次，并使用所有已落库门店计算累计缺失；最后一批完整不能掩盖第一批的缺失。

最终快照新增 queried_id_count 与 missing_ids，前端显示已查询和未返回数量。未返回不等于关闭或不可用。若平台声明数量大于返回 ID 数，仍保持范围不完整。

启动时恢复旧提前结束任务：只允许启用品牌、当前完整基线、当前券观察时间不超过 36 小时且不在未来、明确 STORE_IDS_MISSING、合法范围且还有未查询 ID 的任务。只续查尾批，不反复重试缺失 ID；完成尾批后刷新旧部分快照。全部请求继续使用统一串行门控与 1—2 秒间隔。

## 验证

87 项测试、格式/类型检查及生产构建通过。23 门店用例验证两批都缺失时取得 21 家、只有第一批缺失时取得 22 家，均保持 incomplete；另验证完整 23 家、来源 ID 范围截断、旧任务尾批恢复、过期/未来/停用任务不恢复、恢复幂等及旧部分快照更新。

这项修复改善已知 ID 的查询覆盖，不解决平台未提供剩余门店 ID 的来源缺口；不提高机会评分，也不推断完整店域。
