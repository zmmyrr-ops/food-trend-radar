# AI美食短视频合成：产品与技术方案

版本：方案草案 v1 · 2026-09-29。范围：设计，不代表已开发或已开通模型。

## 1. 结论与示例观察

推荐组合：Qwen3-VL-Flash 初筛 + Qwen3-VL-Plus 精选/编排 + FFmpeg 渲染。复用现有 DeepSeek 做可选字幕文案，不承担视觉判断；一期不购买生成式视频服务，不自建GPU。

用户示例文件本地检测：15.633秒、448×960、30fps，含音轨。抽帧观察到肉品近景、摆盘、蛋黄与浇汁动作，带平台UI，结尾切到手机桌面；本次未转录音轨，不据此判断配乐或口播。借鉴它的食物主体和镜头节奏，输出纯视频画布，不模仿录屏UI或桌面结尾。

当前项目素材模块保存笔记、作者、封面和实况MP4链接，尚无持久媒体库、视觉质检、剪辑时间线与渲染任务。实况MP4可直接剪辑，保留真实动作。静态图片以轻微推拉/平移补位；视频生成模型仅作为后续可选能力，用于允许生成的补充镜头，不虚构券内菜品、份量和门店。

## 2. 产品流程与界面

券卡片保留“获取资源”，增加“制作短视频”。不把编辑器塞进列表；点击进入独立制作页，带返回选券入口。

默认设置：18秒、9:16、简洁美食混剪、无口播；字幕和已授权音乐可开关。支持15/18/20秒。首次只需选模板后点“智能生成预览”，不要求手工逐条筛片。

桌面布局：左侧约一半空间为竖屏预览；右侧为入选素材、替换候选及短理由；底部一行6–8个镜头缩略图时间线；顶部展示券名、素材数量、阶段与取消按钮。高级设置默认折叠。手机按预览、时间线、素材依次排列。

流程：获取资源 → 素材准备 → 智能筛选 → 编排 → 720p预览 → 用户可替换/调序/改字幕 → 1080p导出MP4。每次编辑只重新渲染，不重新抓平台，不重复分析同一媒体。渲染进度来自FFmpeg实际输出时间；模型分析显示已处理数量，不伪造百分比。

素材分为已入选、可替换、已排除三组。默认只看入选片段；排除理由可展开。预览页始终显示“同品牌素材不保证同券同门店”。仅有品牌证据时使用品牌探店模板，不把镜头中的全部菜品描述为该券权益。

## 3. 筛选策略：先规则、后模型、再组合

A. 素材准备：创建项目时固定当前资源ID与券事实版本；在来源允许且具备使用授权时缓存媒体到私有存储，记录内容哈希。原始链接可能过期，不能当成永久资源。对需要刷新来源的请求沿用现有全局3–5秒串行队列，不另开绕过限流的下载循环；429/403暂停，不频繁重试。下载限大小、超时、校验实际媒体格式，避免将Cookie转发到CDN或模型。

B. 本地筛查：FFprobe读取时长/宽高/帧率/旋转/音轨；检测坏文件、黑帧、冻结、严重模糊、极端曝光；按内容哈希及关键帧相似度去重。清晰度阈值按缩放后尺寸校准，不能用一个拉普拉斯阈值机械淘汰所有暗光餐厅。不足1秒或无法安全裁为竖屏的片段进入候补。源分辨率低需标注，输出1080p不宣称恢复了真实细节。

C. 多模态初筛：对每个短MP4提供至少4个带时间戳关键帧，或视频输入；2秒以下片段走多图方式。初筛通常每片4–6帧；入围的动作镜头再用约4–8fps细查。不要只看封面：封面好看不能代表视频不抖、无黑帧。每次分析一个片段，必要时小批多图必须带asset_id分隔，避免串片。

模型返回：主体/菜品标签、镜头类型（特写/动作/全景/环境）、食物可辨识度、视觉吸引力、曝光构图、抖动、遮挡、文字/水印、可裁剪区域、最佳起止时间、与券的匹配级别、排除理由及证据时间戳。置信度仅作待复核标记，不能当作已校准概率。

硬性排除：明显不同品牌、严重损坏/黑屏、屏幕录制UI占据主体、主体不可辨、明确与当前券冲突、没有可用片段。授权缺失的外部素材可留作参考，不能自动进入可发布成片；署名不等于获得授权。对现有水印不做移除功能；优先使用已获授权的源文件。

D. 合格片段质量分（初始规则）：食物主体与相关性30、技术质量25、食欲表现20、动作完整性15、竖屏适配10。相关性须分“同品牌”“同菜品”“有证据对应同券”；看见牛肉不能推断是某档套餐或和牛等级。质量分与券优先分分开。

E. 组合选择：从30–40个候选中选6–8个可用段，不简单取最高分前8名。先按品牌/菜品/门店证据分组；同一道菜最多2段，尽量避免相似构图连排，至少覆盖动作、食物特写、摆盘/组合三类。来源不同也可能重复，按视觉内容聚类去重。同一主体动作连续性优先，不能把两个门店的不同菜拼成一份券套餐。

可用素材不足时先返回15秒版本建议；如果仍不足，不重复循环凑数，也不自动花钱补生成镜头，明确指出缺哪类素材。

## 4. 默认18秒编排

使用以下18秒硬切模板，7个镜头：

- 0–2秒：最吸引人的动作，如浇汁/拉丝/切肉；开头不放长Logo。
- 2–4.5秒：招牌菜近景，建立食物主体。
- 4.5–7秒：第二道菜或另一种质感。
- 7–9.5秒：摆盘/组合全景，让观众理解场景。
- 9.5–12秒：动作镜头，与前段形成节奏变化。
- 12–15秒：食物细节或另一菜品，避免重复堆肉片。
- 15–18秒：最干净的食物画面作为结尾，品牌/已确认优惠信息叠字。

价格只取业务后端最新有效事实，模型不得补价格、节假日可用性、份量或套餐权益。导出前再检查快照有效期；证据不足默认无价格版，可显示品牌名称。每屏最多两行短字幕，放入可配置安全区；页面预览提供平台遮挡参考线，但不烘焙到成片。

默认硬切，少量叠化不超过0.15秒；如启用叠化，计算输出时长=片段和−叠化重叠，时间线必须补足目标时长。MP4段通常截取1.5–3秒，不拉长冻结尾帧；静态照片最多约30%时长，轻微推拉不生成食物动作。原素材音频默认静音，可选择已授权BGM，结尾短淡出。口播二期再加，不能默认沿用别人笔记的音乐。

## 5. 模型选择与对比实验

首选视觉初筛：qwen3-vl-flash-2026-01-22，非思考模式。用于大批素材标签、排除原因、基础视觉判断。首选精选/全片复核：qwen3-vl-plus-2025-12-19，非思考模式；只分析约8–12个候选、边界案例与成片抽帧。固定快照模型并记录版本，避免别名静默升级影响评分。

官方文档确认Qwen3-VL支持视频或帧列表输入；视频接口不理解音轨，因此音乐节拍、音量、静音检测由本地程序处理。模型边界时间必须映射到实际帧并验证，不直接信任模型给出的时间。能力依据：[视觉理解官方文档](https://help.aliyun.com/zh/model-studio/vision)。

备选：Doubao-Seed-2.0-lite，优先核验控制台可开通的260428快照。官方公告说明其支持视频、图像、音频和文本理解，可用作需要音画联合判断时的对比组；是否更适合食物素材，需要用本项目样本验证，不先断言质量胜出。依据：[官方发布说明](https://developer.volcengine.com/articles/7636596381943070763)、[Chat API](https://docs.volcengine.com/docs/ark/chat-api?lang=zh&redirect=1)。

现有DeepSeek调用保持文本职责：根据视觉模型已输出的标签及后端券事实生成镜头顺序或短字幕。一期也可以让Plus同时输出剪辑计划，减少一次模型往返；不为复用已有Key而把未核验的视觉能力当作已支持。

生成式视频（例如Seedance系列）只列为二期可选实验：静态图需要新运动时逐镜头生成，再剪辑；需单独评测菜品形态、文字、份量一致性与费用。当前实况MP4已有运动，一期没有必须使用生成模型的环节。

选型验证：取5–10个品牌、100个授权素材片段，标注相关性、可用性、最佳区间及去重组；Flash与备选盲评，Plus处理分歧。核心衡量：不相关误入率、严重画质问题漏检率、动作完整率、人工换片次数、单任务费用和延迟；成本低但错把其他套餐剪进来的模型不合格。阈值在这批样本上调整后，用另30个未参与调参片段验收。

## 6. 成本与耗时

截至2026-09-29查阅百炼北京地域价目，在单次输入≤32K Token档：Flash输入0.15元/百万Token、输出1.5元/百万Token；Plus输入1元/百万Token、输出10元/百万Token。更长单次请求进入不同档位。来源：[官方计费](https://help.aliyun.com/zh/model-studio/model-pricing)。

算例仅用于预算，不是本项目实测：假设一任务累计Flash输入60,000/输出6,000 Token（拆成每请求≤32K），Plus输入20,000/输出3,000 Token，视觉模型费用=0.009+0.009+0.020+0.030=0.068元。未包括重试、DeepSeek、存储、带宽、音乐、配音或生成视频。实际按响应usage记账；视觉Token取决于帧数与像素，不按“40张图固定价格”报价。

初期可设视觉调用预算0.5元/任务、最高1元硬上限（可配置），超限暂停并保留成果；建议先跑10次样本获得P50/P95实际成本再定价。缓存键含媒体哈希、抽帧策略、模型快照及提示词版本；替换/改字幕尽量只重渲染。

完成时间初步工程目标：缓存素材18秒成片预览P95≤5分钟，待ECS压测；不承诺实测前的秒数。首次抓素材时间单独计算，保持现有3–5秒串行，不能因制作任务提高抓取频率。

## 7. 技术架构与任务闭环

React制作页 → Node API创建任务 → 数据库任务表 → 独立Node媒体Worker → 下载/FFprobe/抽帧 → 视觉模型 → JSON剪辑计划校验 → FFmpeg预览/导出 → 私有对象存储 → 鉴权下载。

MVP沿用PGlite，由现有API进程独占数据库；媒体Worker通过本机受控接口领取任务和回传结果，绝不能第二进程同时打开同一PGlite目录。任务量增加再迁移PostgreSQL/Redis队列，不为一期先引入整套新基础设施。

媒体worker独立systemd服务，渲染并发1、线程上限2，设置CPU/内存/磁盘配额和超时，与券采集隔离；现有ECS规格需上线前核验，不假定它可无压力承担1080p渲染。模型初始并发1–2，429遵循Retry-After，指数退避最多2次；费用不足/认证失败不自动重试。

模型只返回结构化JSON，不能返回可执行shell。字段：asset_id、source_in/source_out、role、crop(normalized)、caption、transition、reason；后端使用Zod验证资源归属、时间不越界、时长之和、裁剪范围和事实引用。FFmpeg通过参数数组spawn，输入全部为校验后的本地文件，隔离网络访问；字幕文本转义，限制分辨率和最大任务时长。

渲染：统一旋转方向、尺寸、帧率、SAR、timebase、像素格式；导出H.264/yuv420p、AAC（选择音轨时）、MP4 faststart，默认1080×1920、30fps，预览720×1280。优先主体安全裁剪，无法裁剪用背景衬底，不硬拉伸。FFmpeg负责精确trim/concat/字幕/音量，不让生成模型承担精确秒数或价格排版。依据：[FFmpeg滤镜文档](https://ffmpeg.org/ffmpeg-filters.html)。

媒体下载防SSRF：仅批准的来源域名，禁私网/回环IP，每次跳转重新校验；有大小上限与内容类型校验。模型API Key只在服务端。模型读取经授权缓存的文件或短效签名URL，不发送小红书Cookie/抓取签名。成片下载沿用站点鉴权，OSS不设公共读。

## 8. 数据与API

media_assets：id、resource_id、note_id、author、source_url、sha256、object_key、mime、width/height、duration/fps、rights_status/evidence、created_at/expire_at。

media_analyses：asset_id、model_id、prompt_version、sampling_version、quality_components、labels、best_segments、match_level、evidence_times、reject_reasons、input/output_tokens、cost。

video_projects：id、brand_id、product_id、coupon_fact_snapshot、template_version、target_seconds、aspect_ratio、caption_mode、music_asset_id、timeline_json、revision。

video_jobs：id、project_id/revision、idempotency_key、stage、progress、lease/heartbeat、attempt、cancel_requested、error_code、budget、actual_cost、output_key、created/finished_at。

POST /api/v3/video-projects 创建；POST /:id/analyze 分析；GET /:id 读状态与结果；PATCH /:id/timeline 改计划并递增revision；POST /:id/preview 预览；POST /:id/export 导出；POST /video-jobs/:id/cancel 取消；GET /:id/download 鉴权下载。路径统一前缀/api/v3/video-projects，job取消单独使用/api/v3/video-jobs。所有变更绑定项目权限、修订号与幂等键。

状态：queued → preparing → analyzing → planning → rendering_preview → preview_ready → rendering_export → completed；异常为failed/paused/cancelled。失败按阶段恢复，已成功分析不重复扣费。重启由租约识别中断任务；取消终止子进程但保留已完成分析。输出先写临时对象，校验完成后原子发布，避免提供半个MP4。

## 9. 质量验收、清理与实施顺序

自动验收：文件可完整解码、15–20秒且与目标偏差≤1帧、无意外黑尾/冻结/空音轨，字幕不越界、价格来自对应券事实，所有片段可回溯。自动检查只能筛明显缺陷；视觉美感与券匹配不能仅靠模型自评分验收。

样本验收目标：20个制作任务全部满足时长/解码；人工盲评至少16个无需重做可用；明确跨品牌和已知错误权益素材0个误入；取消不产生继续付费调用；刷新不丢任务；同素材再剪不重复视觉计费。包括素材不足、链接过期、多规格券、无原价、模型超时、ECS重启场景。

存储建议：抽帧临时文件24小时、来源缓存7天、成片30天，均可配置；保留使用来源与编辑计划。清理必须避开正在运行的任务，并记录删除结果。没有授权不自动导出可发布版本；允许上传自有/品牌授权素材补位。此功能不自动发布到社交平台。

阶段一（约2–3工作日，工程估算）：授权素材上传/缓存、FFmpeg模板、18秒预览与下载，先跑通确定性剪辑。验收：不用AI也能用指定片段产出正确时长。

阶段二（约2–3工作日）：Flash/Plus适配、规则初筛、去重、剪辑计划、成本日志。验收：100片段选型测试和30片段留出验证。

阶段三（约1–2工作日）：简洁制作页、换片与调序、进度取消、缓存重试与线上资源限制。验收：20任务回归与ECS压测。共约5–8工作日取决于凭据、授权素材、现有服务器负载，不是交付承诺。

一期完成即具备：券 → 获取资源 → 自动筛片 → 15–20秒预览 → 少量可选修改 → MP4导出。后续再考虑卡音乐节拍、配音、多模板与生成式补镜头；不把这些追加为一期阻塞项。

## 2026-09-30 实施更新

素材区增加“再找一些”，每批目标新增20个；复用已有结果、按媒体路径去重，持久化搜索页码和已检查笔记。单次最多搜索3页、检查20篇笔记，继续沿用全局3–5秒串行请求和风控停止机制。单券最多保留200个，结果不足时如实展示，不填充无关内容。视频任务仍最多选择40个素材，默认选最近获取的40个。

视觉初筛调整为6帧，提升抽帧尺寸并按清晰曝光、食欲感、构图、可剪辑连续性评分；分析缓存升级为v2。精选提示词增加动作/质感开场、景别交替、菜品逻辑和成品收尾要求，最终剪辑保留模型给出的镜头顺序。接近9:16的素材使用轻微裁切铺满画面，其余保持原比例；增加短暂首尾淡入淡出并提高编码质量。仍为抽帧判断，并非完整视频动作理解；新增要求不意味着每条成片都能达到同等质量。已有成片不自动覆盖，重新制作才应用新流程。

### 自动连贯字幕

新视频完成镜头编排后自动生成字幕。Qwen3-VL-Plus读取每个最终裁切片段的代表帧和商家、券快照，Qwen-Plus将画面资料整理为连贯文案；按镜头序号填入时间线并生成带字幕预览。字幕校验包括数量、序号、字数和部分不适当描述，校验失败时最多自动压缩改写一次，仍失败则保留原时间线。已有视频可点击“AI生成连贯字幕”；修改后的字幕可以一键复制。生成字幕会提高修订号，旧导出不作为当前版本下载，需重新导出。字幕仍需用户核对，尤其素材属于同品牌不等于该券所含菜品。
