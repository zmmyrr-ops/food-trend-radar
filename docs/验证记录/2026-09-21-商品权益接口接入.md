# 商品权益接口接入与验证

发现路径：官方选品页面 JS 中的 GetGoodsProductCommodityDetail，GET `/life/alliance/v2/goods/product/commodity/detail/get`，参数 from_type=5、product_id。不是猜测接口路径。只使用现有 eos.douyin.com 会话，不向其他主机传递凭据。

## 真实证据

牛New 商品 1876640352505867 返回单人工作日精选超值版自助畅吃 1 份，以及购买后 7 天内有效、周六周日/部分节假日不可用、11:00—11:30 与 16:30—17:30 可用、每人每天最多 2 份、预约/退款/儿童价格等须知。牛New 全部 9 张名称匹配券补采完成。

页面通过真实浏览器选择牛New并打开该券规则，已看到这些实际限制、采集时间以及首次规则基线说明。白名单样本位于 apps/api/test/fixtures/commodity-sanitized.json，不保留 Cookie、账号信息或签名图片地址。

## 已实现

- 新增 coupon_rule_tasks 与 coupon_rule_snapshots。按采集轮次+商品去重，复用相同商品规则；前端显示真实规则采集时点，不冒充与价格同时采集。
- 列表与规则共用同一个 SerialGate/worker。列表任务优先，规则在列表空闲时逐张采集，请求结束后等待 1—2 秒。鉴权/429/业务结构异常停采，网络失败限次退避。
- 完成品牌快照后自动排队名称匹配商品；已有 2,744 张匹配券已触发补采，不需要日常逐券录入。新基线替代的旧规则任务标记 superseded。
- 返回套餐和规则才标 complete；字段不足标 incomplete；这两种状态都不等于已经满足完整可比性。
- API：POST /api/v3/rules/backfill（可选 brand_id）、GET /api/v3/rules/status、GET /api/v3/coupons/:id/rules、GET /api/v3/brand-coverage。
- 页面查看套餐与购买须知、首次规则基线与两次规则文本/商品字段变化提示、运行健康规则队列统计、品牌归属诊断。

## 验证与剩余

npm run check：33 项测试通过，格式、类型和生产构建通过。新增真实规则脱敏/指纹、列表与规则共用门控、鉴权暂停、恢复续采和队列幂等测试。品牌覆盖诊断实测 122/150/26/10 四类，共 308 品牌。

仍待规则全量补采、自然语言条件结构化、适用门店与身份核验；文本变化不直接等于性价比提升。门店列表单次探测遭遇重定向，未自动跟随；该来源尚未接通。
