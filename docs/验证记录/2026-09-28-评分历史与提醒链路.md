# 评分历史、观察排序与提醒链路

## 本轮完成

实际商品和对应轮次规则、门店证据进入后台评分任务。每分钟最多处理 100 个品牌×券，优先检查尚未评估或检查时间最早的记录，避免每分钟只处理列表前几条。仍不调用大模型，不新增平台请求。

每条评分保存模型版本、证据快照、缺失原因、区间、门槛及证据版本哈希。连续两次证据相同不重复保存；补采、证据过期或证据回退会保存新版本。历史按品牌隔离，不能把其他轮次的新详情补入旧评分。

当前来源只能确认一部分完整店域中的上海证据。品牌身份、完整权益、可售及达人覆盖没有被自动设为通过。价格下降线索不能直接填入已核验价值分；热度和达人缺失仍保存为空，不填零。

接口：

- GET /api/v3/coupons/:id/scores?brand_id=...：最近 100 条评分版本。
- GET /api/v3/rankings?gate=watch：已评分的当前新鲜基线观察区，按分数下界及评分时间排序，最多 100 条。
- GET /api/v3/rankings?gate=eligible：满足所有门槛的推荐区；当前为空是预期结果。

每次计算调用现有站内机会提醒入口，仍要求全部门槛通过、确认变化和下界至少 70。提醒按品牌、券、证据及规则版本去重；证据不足不会提醒。前端券卡已加入“查看评分记录与依据”，等待评估时明确显示暂无记录。

## 仍受阻

1. 严格同权益比较需要完整门店范围、资格、附加费用及品牌归属证据。部分商品只返回部分门店 ID，不能推断剩余范围。
2. 原始商品响应中发现的 creator/video 等名称主要是 ab_params 功能开关，不能用作达人数量或热度。公开前端脚本的本次排查也没有提供经验证的替代数据接口。
3. 同券达人覆盖、品牌指数没有取得已验证自动来源；当前观察区间可能相同，这是缺失输入的表现，不是计算出了相同爆款概率。
4. 常驻启动、7 天连续运行及结果标签回测仍未通过。该功能完成不解除这些条件。
