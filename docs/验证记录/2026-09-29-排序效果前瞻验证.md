# 排序效果前瞻验证

对应现有 TODO「选券效果验收」，不是关注跟踪扩展。

## 运行方式

后台每分钟检查，但每个上海半日只保存首次非空优先券榜单一次。冻结实际保存时间、priority-v2 分项、缺失情况、券身份、查询口径、原月售速度、原始指数和排序。首批可能来自不同品牌的最新完整基线，不声称是全品牌同时观测，也不回填过去榜单。

保存后72小时进入核对窗口，以72—84小时内首次可见的后续观测计算结果。使用后续采样窗口的月售展示净增速度，而不是把滚动月售差称为72小时新增销量。名称、查询口径变化或后续速度不可比则标记不可用；到84小时仍无观测则记录缺失。未知不置零；负速度如实保留。用户后来隐藏券不影响后台读取后续热度。

每半日分别统计前20张和其余优先券的待观察、可核对、缺失/不可比数量，以及仅在可核对样本上的平均速度、正速度占比。接口 `/api/v3/pick-evaluation` 返回最近14批汇总和每批前20张明细，完整冻结记录保存在本机数据库。首页「查看排序效果验证」展示汇总。

## 边界

这是观察性前瞻结果，不是因果实验、爆款命中率或经过校准的概率。同品牌多券相关，缺失样本可能有偏差，不能仅凭均值证明模型有效。关机/休眠可能错过观察窗口并产生缺失。原始全部权益连续性仍未完全核验。当前不自动调整评分权重。
