# 自动公告观察链路 · 首批验收

2026-09-20。首批范围仅一个真实来源／一个品牌，不代表150—200品牌监测或完整M1验收。

## 已交付

- 来源：麦当劳中国官网 https://www.mcdonalds.com.cn/news/sales 。读取公开HTML，先检查robots，固定域名与路径，不跟随跳转，不调用被禁止的API。采集只存公告标题、日期、链接及分类结果，不保存图片、营销正文或个人信息。
- Node.js服务启动后检查是否到期，每6小时自动采集；网页可立即更新，至少间隔5分钟且同一进程禁止并行任务。服务必须运行；电脑休眠或关闭后不持续执行，重启后按最后任务时间检查补采。
- 每次读取当前网页可返回的公告列表，没有假设它涵盖所有历史。URL稳定去重；内容变化追加修订；首次可用时间取本次实际采集时间，历史发布日期不会改成今天。
- 迁移v7建立auto_runs、auto_signals、auto_signal_revisions、auto_scores。信号写入、修订、分数快照与成功状态在同一事务提交。中断任务在启动时标记，后续到期重新读列表。
- GET /v1/opportunities返回真实榜单、来源、覆盖数量和最近10次任务；POST /v1/auto/update异步触发，接受时返回202，运行中或冷却期返回409。
- 默认首页改为自动榜单，显示来源时间、分数组成、近期公告链接和错误原因。每5秒刷新查询，不等于每5秒请求外部来源。超过12小时未成功采集，榜单当前分数下线。

## OBS-announcement-v1口径

仅用于验证“自动读取→确定性计算→结果展示”。这是公告优先级，不衡量真实需求或预计传播量，也不是旧八因子模型的缩水版本。

1. 标题按冻结关键词规则识别新品、联名、优惠或节日限定；不支持的标题不评分，命中风险词的不评分。标题识别尚不代表完整活动事实核验。
2. 原文只提供日级发布日期，按上海当日00:00记录并标注day精度。公告年龄A以计算时点减发布日期计算；未来公告日期或年龄超过14天不评分。
3. 新鲜度贡献=round(70×(1−A/14),1)；活动标题命中贡献=30；公告观察分为两者之和。没有用初次采集时间奖励旧公告。
4. 品牌分取本轮最高合格公告分，同分按URL稳定排序；保存所有合格信号和贡献。页面显示的是最近成功任务的分数及真实计算时点，不把轮询时间伪装计算时间。
5. effective_price、活动开始结束、上海参与情况均不从标题猜测；早期信号分、p72、正式抢跑指数为null。全国公告只作观察线索，不进入可拍推荐。

## 实测与测试

首次实际运行成功：读取1,709条公告元数据（含历史），6条在14天范围内且符合标题规则；1品牌可评分，人工事件表仍为0。麦当劳观察分75.9，计算时间2026-09-20 19:45:58（上海）；该数只适用于该次快照。

8项测试全部通过，类型／格式检查与生产构建通过。新增自动链路测试覆盖：日期非法、未来日期、历史过期、风险词、域名限制、同URL去重、重复运行、修订留痕、旧快照不覆盖、来源失败、12小时过期、重启中断恢复、不写人工事件。浏览器核对首页真实结果和字段展示。
