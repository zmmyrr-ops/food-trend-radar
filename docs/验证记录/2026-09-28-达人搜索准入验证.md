# 达人搜索来源验证与检索准备

## 实际结论

本阶段没有采集到真实视频，自动搜索与真实达人减分仍未完成。浏览器以“绝味鸭脖 120元代金券 110”打开抖音搜索超时（30 秒），随后首页验证也超时（45 秒）；不能据此判断账号被封、需要登录，或平台没有相关内容。没有循环重试或批量查询，也没有将选品 Cookie 发送给视频搜索主机。

核查[官方视频搜索文档](https://developer.open-douyin.com/docs/resource/zh-CN/dop/develop/openapi/douyin-search-capability/aweme-dy-video-search)：需要 aweme.dy.video_search 能力及 client token；示例包含视频标识、发布时间、昵称、点赞、正文、游标和搜索标识。示例未证明有稳定作者 ID 或具体券版本关联。项目当前只有选品会话文件，没有配置搜索应用凭据；文档描述不等于真实调用成功。

## 已实现

- GET /api/v3/creator-search 从当前机会自动生成检索准备，支持品牌筛选。暂不考虑和历史再现不进入方案，当前版本变化更新方案 ID。
- 保留代金券面额与成交价区别，范围价不伪造唯一价格。检索链接仅用于来源验证，不是自动采集完成标志；不要求用户日常录入。
- 页面“同券达人覆盖”展示来源阻塞、检索词、所需字段、同券匹配条件；人数/视频数/增速为空，扣分保持 0—30 的未知区间。
- 既有统计纯函数补充近 24 小时、前一 24 小时统计和增速。零基数或覆盖不明不输出增速；同视频不同作者/发布时间、观察先于发布、券关联未知均不能获得完整覆盖。仅标题/价格相同仍只是候选，未实现自动确认同券。

## 验收

npm run check 通过：格式、类型、103 项测试及生产构建。新增测试覆盖检索词和版本、范围价、未知值、API 筛选、非法品牌参数、视频冲突顺序无关性、时间异常、24 小时边界和零基数。

运行服务更新后，真实 API 自动生成 3 张机会券的计划：绝味 120 元券/110 元成交价、绝味 100 元券/92 元成交价、DQ 抹茶暴风雪/33 元成交价。全部仍为 blocked_source，automatic_collection=false，无伪造视频写入。页面展示与展开检索准备已验证。

采集恢复 enabled=true、pause_reason=null、concurrency=1、interval_ms=[1000,2000]。新增功能不发平台后台请求。

真实 API 记录：data/reports/creator-search-verification-20260928.json。

## 下一项明确依赖

需要能实际访问的抖音网页搜索会话，或具有视频搜索权限的开放平台应用/授权数据服务。拿到真实返回后，先验证稳定作者 ID、时间、正文和券关联证据，再实现适配器及自动调度。搜索分页结束也不能自行证明平台全量覆盖，不会直接按无结果扣 0 分。
