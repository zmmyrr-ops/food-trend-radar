# 同券条件联合比较

## 实现范围

新增只读接口 `GET /api/v3/coupons/:id/condition-comparison?brand_id=<UUID>`。按品牌当前完整基线与任务记录的 `previous_run_id` 查同一商品，每份规则/门店只关联对应 `run_id + product_id`。本轮未命中返回 404，不将旧商品当作当前可售。

输出包括票面价差、套餐与日期/时段等规则变化、门店新增/减少 ID、上海证据数量、采集时间与阻塞原因。页面每张券可点击“查看同券条件比较”，只读本地记录，不发额外上游请求。

三种线索：

- 票面降价且已返回条件一致：两轮规则和完整门店可对比，返回条件及关键券字段均未改变。
- 票面降价但条件未确认：价差已知，但规则或门店变化/缺失。
- 尚无确认优惠提升：无可比较基线、无降价或当前快照过期等。

上述全部保持 `value_verdict=unverified`，不触发机会加分或推荐告警。返回文本一致不能证明资格、费用及其他例外已完整解释。当前只处理同商品 ID；不将不同 ID 的同价套餐直接归为可比。

## 时间边界

- 当前券快照只在 36 小时内提供降价线索。
- 详情采集必须不早于所属券快照、不晚于读取时间，且在该快照后 36 小时内。
- 上轮详情必须在本轮券价采集前取得，避免把后续规则倒填到历史。
- 首次基线、过期基线、查询口径切换不输出跨轮价差。
- 价格与补采不是原子快照，仍保留来源时间；不能据此宣称某一瞬间全部条件同时成立。
