# 运行耗时诊断

针对 P1-4d-2b 的间歇卡顿补齐观测能力，本次不宣称卡顿根因已解决。

## 已实现

- `/api/v3/runtime-diagnostics` 直接读取内存，不执行数据库查询；仍受现有本机访问限制。
- 记录数据库 query、transaction 调用及后台评分刷新、简报、热度读取、备份、天气更新阶段的耗时、在途数量、调用文件/行号和是否失败。
- SQL 仅保存 SHA-256 截断指纹；不保存 SQL、参数、凭据、数据结果或异常正文。耗时包括排队，不能视作纯 SQL 执行时间；步骤/查询存在嵌套，pending 不是独立请求数。
- 最近 100 次超过 250 毫秒的调用；最多保存 200 个在途调用明细，计数仍反映全部。定时采样事件循环延迟。
- 独立于数据库报告流程，每 10 秒原子写入 `data/reports/runtime-diagnostics-current.json`，权限 0600。重启前一份记录保留为 `.previous`；正常退出写出最终状态。不依赖定时品牌轮次完成。
- 事件循环完全阻塞时内存接口与文件更新也会延迟，不能宣传为独立进程看门狗。文件写入失败不破坏采集，下次成功写入会记录前次写入失败标志。
