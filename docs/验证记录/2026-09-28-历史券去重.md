# 历史券去重与首次发现口径修正

真实核查发现：原机会榜中 15 条首次发现有 14 条曾在 9 月 20 日或 21 日的完整快照出现过，只是紧邻上一轮未见。它们不能继续作为系统首次发现。

实现：

- 使用同品牌、同商品 ID 的历史完整任务记录，查询最早观察时间；不跨品牌混用历史，也不把失败任务升级为完整历史。
- 上轮未见、历史已见的券改为“历史券再次出现”，提供最早完整记录时间及独立筛选，排除默认榜单和新机会摘要。真正发生降价不因曾出现过而排除。
- 优先补采同步使用历史去重条件；历史券再次出现及普通字段更新回到普通队列，仍保留每四次一次的普通任务机会。没有新增并发请求。
- 验收统计将同价增量与降价分别计数，避免同价增量被纳入降价数量。
- 数据库新增品牌/商品/观察时间索引供历史查询使用。历史采集记录保持原样，不回写旧价格或旧差异事件。

验证包含分类纯函数、真实 HTTP/独立数据库历史查询、失败与完整任务的区分、默认榜与历史再现筛选、两类补采队列排序。78 项回归及类型、格式、构建检查通过后部署。

部署核查：真实 API 默认榜从 17 条变为 3 条（2 条票面降价、1 条首次完整记录）；历史再次出现筛选为 14 条。页面已确认显示相同计数，DQ 首次记录只剩抹茶暴风雪系列 33 元这一条，仍不认定平台新上架。检查时扫描 282/308 品牌，采集已恢复。真实结果保存 `data/reports/history-dedup-verification-20260928.json`。
