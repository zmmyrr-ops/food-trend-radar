# 上海美食优惠券机会雷达 产品需求文档

版本 V3.0 | 2026-09-20 | 上海 | React + Node.js

## 1 产品方向与业务闭环

### 定位与替代范围

V3 以“优惠券变化驱动的美食选题雷达”为产品主线，为上海美食创作者筛选值得及时跟进的品牌团购券。每日北京时间 00:00 和 12:00 扫描品牌池，比较历史优惠，再结合达人内容饱和度、品牌近期热度以及天气节假日生成可解释的选题优先分。

### 旧概念退出

旧版八因子权重、未来 72 小时爆款概率和抢跑指数不再作为本期指标与验收目标。新主指标为 0—100 的“券选题机会分”，它是规则评分，不是爆款概率。未来 72 小时仅用作天气和券可使用性的观察窗口。旧数据保留，旧榜单不能混入新榜单。

### 用户与覆盖

主要用户是上海美食探店、团购测评和短视频创作者。沿用当前 308 个品牌候选，所有启用品牌均应生成扫描任务；品牌无券、搜索误匹配、采集失败、覆盖不完整分别展示。品牌数量不等于已接入数量，同品牌多个门店不重复计为品牌。

### 业务流程

全量品牌任务 → 串行检索并翻页 → 品牌及上海适用性核验 → 保存券快照 → 对比上次成功快照 → 识别上新或更优惠 → 检索该品牌该券的达人内容 → 补充品牌指数和环境信息 → 计算机会分与证据完整度 → 排序、站内提醒、持续复核。

### 日常操作

用户只需查看结果、筛选品牌或品类并打开证据；不需要人工输入券或逐次复制请求。首次授权及会话失效时的重新登录是必要操作。接口或数据源不可用时系统显示缺口，不把维护表单作为日常替代流程。

## 2 采集与券变化判定

### 采集节奏

时区固定 Asia/Shanghai，每日 00:00、12:00 创建轮次。全局采集并发为 1，上一请求结束后随机等待 1—2 秒再发下一请求，覆盖搜索、翻页、详情、达人及重试请求。没有人工更新、补采或重试的旁路。遇限流应延长等待或停采，不能把 1—2 秒当作账号安全保证。

### 轮次完成与覆盖

扫描按品牌逐个执行，轮次启动时间不是所有品牌同一观测时点。对每个品牌记录实际观测时间、页数、完成状态和失败原因。分页上限或错误造成的截断标为部分完成。下一轮到点时若旧轮仍在运行，不启动第二个采集器；合并待执行触发，显示调度延迟。

### 比对基线

与同品牌、同城市、同查询策略和覆盖口径的上一次成功完整快照比较，不能用部分页或失败结果替换基线。首次完整扫描只建立基线；此前没见过的券叫“首次发现”，只有销售开始时间等可靠证据才能标记“已证实上新”。旧快照超过 36 小时标记基线陈旧，降低变化结论可信度。

### 变化类别

保存 NEW_OBSERVED 首次发现、NEW_CONFIRMED 已证实上新、PRICE_DROP 同规格降价、BENEFIT_UPGRADE 同价权益提升、RESTRICTION_RELAXED 限制放宽、UNCHANGED 无变化、NOT_SEEN 本轮未见、UNAVAILABLE 已证实不可售。仅因搜索结果消失不能断言下架。

### 对比对象

同券 ID 的规格或权益也可能变更；不同 ID 也可能对应等价套餐。比对品牌、商品组合、数量或人数、净含量、适用门店、使用时段、期限、新客会员条件、最低消费及附加费。归属或关键条件不明时，仅列待核验，不进入强推荐。

## 3 性价比与内容环境规则

### 同价与更优惠

初始同价容差为 max(1 元, 上次实际售价×3%)，以旧券价格为参照并版本化。只有券类型、使用资格、店域及限制可比时，才比较价格和权益。若新价更低且权益不减，或同价权益数量提升且限制不加重，可判更优惠。涨价换更贵食材、不同档次自助餐或多人套餐不可直接凭字面价值判优。

### 计算边界

实付价包含已知必付附加费。充值门槛、新客或会员专享单列，不与普通券混排。折扣券记录门槛、封顶、叠加条件；储值券与消费券分组。标称原价仅作证据，不能单独用于性价比分。原价为 0 或未知视为缺失；销售结束时间不等于核销有效期。

### 达人饱和度

对入选候选搜索“品牌＋券名或套餐关键项＋价格”，观察近 7 天并重点看近 72 小时。按视频 ID 与独立作者去重，核验品牌、券版本、价格和内容发布时间；无关品牌热帖不扣分。内容达到一定规模时扣分，而不是给达人集中发布加分。搜索只覆盖样本，不能宣称平台全量作者数。

### 品牌热度

优先对接可持续取得的抖音指数，其他平台指数作为补充。分别看最近完整 7 天的热度水平和相对过去 28 天的变化，同平台同口径标准化。粉丝量、搜索结果数及商品月售不能冒充搜索指数。未接入的平台显示缺失，不凭空填数，也不要求每个平台都有数据才展示券。

### 环境因素

按未来 72 小时上海天气预报、节假日及调休日评估销售适配。冷饮、高温；火锅、降温等属于待检验的品类假设，应低权重使用。强降雨对到店可达性可以产生负向影响；节假日并非一律加分，必须结合券是否可用、店铺营业和预约限制。

## 4 评分与结果展示

### 评分公式

V3 初始规则：S = clip(0.60V + 0.15N + 0.15H + 0.10E − D, 0, 100)。V 为优惠价值，N 为变化新鲜度，H 为品牌热度，E 为环境适配，各为 0—100；D 为达人饱和扣分，范围 0—30。权重是可调整的业务初值，不是统计验证后的预测参数。

### 优惠价值 V

V = 0.60I + 0.25A + 0.15U。I 为改善幅度：同规格降价比例或同价同质权益增量映射至 0—100；A 为近 30 天同类可比券的单位价格优势百分位；U 为使用便利度，包括可用时段、门店覆盖、期限和资格门槛。首次发现券没有旧价时 I 未知；可有 A，但不得伪造改善幅度。

### 新鲜度与达人扣分

已证实上新或已核实改善，在证据时间起 24 小时内 N=100，24—48 小时 N=70，48—72 小时 N=40，超过 72 小时 N=10；首次发现但未证实变化时 N=30 且标注发现时间。达人扣分初值按有效样本近 72 小时独立作者数：0—4 人扣 0，5—14 人扣 10，15—29 人扣 20，30 人及以上扣 30。样本不足时不能据零结果认定无人发布。

### 缺失与排序

不以 0 分填补缺失，不把缺失权重分摊给已知项。各未知输入按其取值范围生成 S 下界与上界，同时显示证据完整度。V 的内部缺失也逐项传播区间。只有品牌及上海适用可核验、价值证据足够且 D 可评估的候选能进入推荐榜；其余进入观察榜。推荐榜按分数下界排序，分数区间重叠时按价值改善和数据新鲜度排序。

### 页面与提醒

首页分推荐、观察、数据异常三个视图；券详情展示新旧差异、实付及限制、各项贡献、达人证据、指数和天气时点。S 下界≥70 且有确认改善或上新时列为优先关注，50—69 普通关注；这些是初始阈值。站内提醒对同一变化去重，只有价格、权益或等级实质变化再提醒；外部推送后续单独配置。

## 5 落地范围与验收

### MVP 边界

先交付两次日扫描、串行限速、真实券快照、品牌归属、差异对比和可解释观察榜，再按数据可得性接入达人、热度、天气与节假日。未接入的维度保留缺失或区间，不能在 MVP 冒称四因素完整评分。优惠券入口已验证可返回商品，不代表所有品牌都能精准命中或获取详情。

### 数据事实与缺口

2026 年 9 月 20 日实测：选品广场查询 4 次返回 48 个不同商品，翻页可用；瑞幸样本含品牌 ID、售价和月售。牛New 搜索出现其他商家，精准归属仍待解决。达人搜索采集、各平台指数、完整适用门店与核销规则尚未完成接入验证。

### 质量与账号保护

请求凭据仅本地安全保存，不出现在前端、日志或文档。401/403、验证码或风控业务码暂停对应来源；429 优先遵循 Retry-After。串行和间隔只能降低请求密度，不能保证不封号。不使用轮换账号、代理或破解签名规避限制。

### 验收标准

全量启用品牌均有扫描状态；分页完整性可审计；模拟并发触发也只有一个请求在途且完成后至少间隔 1 秒。缺失页不能产生下架结论。可重放真实样本得到相同差异与分数。验证新客条件、会员价格、加价换套餐、同名品牌及首次基线等反例。连续 7 天 14 个轮次形成真实运行记录；异常轮次保留并修复，禁止伪造成功。

### 效果校准

前 2 周积累采集质量与候选样本，后续按时间顺序评估 Top 10 有效优惠率、误归属率和内容机会。没有未来内容表现数据时只评估数据和比价质量。月售变化不能当作 72 小时销量标签。至少积累 4—8 周后再检查权重与阈值，具体上线取决于样本量及误差，不按日期自动认定有效。


## 2026-09-28 已实现增补：选题工作台

- 同券线索支持关键词、最低票面降价金额/比例筛选和排序，筛选不影响算法评分或后台采集。
- 跨券 ID 比价要求同品牌平台 ID、同列示套餐数量/单位和相同返回条款；排除任选、缺量/单位、上轮补采时间越界以及已知完整店域不同。只报告低于上轮同组最低价的线索，不声称完整同权益或新品。
- 动态简报合并同券变化与跨券匹配，避免同一券首次发现与跨券线索重复展示；每分钟根据证据更新，下载 Markdown 保留原文来源时间、价格和缺口。扫描完成提醒仍为当时的历史摘要。
- 连续调度验收显示最近 14 个结束时段的结果，手动扫描不能抵扣漏跑，验收条件是该时段内全部已创建任务完成且无小于 1 秒间隔。不能替代权益验收、品牌全量覆盖或逐秒在线率。


## 2026-09-28：未来 72 小时使用限制落地

基于当前品牌完整轮次的价格与规则证据，以 Asia/Shanghai 日期切分滚动 72 小时（非午夜通常跨 4 个日历日），识别完整、无例外的明确禁用日期、日期区间、星期和命名节假日。未识别的日期条款保留原文，泛称法定节假日不自动映射为全部放假日期；2026 年以外命名节假日保持未知。时段保留秒与跨夜标记，只展示条款，不推断门店营业时间。

价格须在当前 36 小时内，规则须不早于价格且不晚于当前时间；缺失和过期不借用旧规则。购买后有效天数不从采集时刻起算。输出仅有明确禁用或未确认，不输出已确认可用，也不提高环境分或完整权益等级。

新增 GET /api/v3/coupons/:id/use-outlook?brand_id=UUID；机会榜、跨券匹配和当前规则 API 携带 use_outlook，简报带禁用日期。机会榜支持 usage=any|has_exclusions|not_fully_excluded，在分页前筛选。全部基于已落库数据计算，无额外平台请求。


## 2026-09-28：达人搜索准备与准入边界

GET /api/v3/creator-search（可选 brand_id）直接使用当前机会榜候选，按品牌、券名、固定成交价生成检索方案，方案随券 revision 变化；暂不考虑与历史再现不进入计划。范围价不冒充唯一成交价。此接口不触发外部采集，automatic_collection=false，状态 blocked_source，真实人数与视频数为 null，扣分保留 0—30。网页检索链接用于来源验证，不要求用户日常人工录入。

当前尚无真实搜索样本。官方文档提供视频 ID、发布时间、昵称与点赞示例；作者稳定 ID 和具体券版本关联尚未验证，不可用昵称去重。搜索分页结束不等于平台全部视频覆盖。统计算法新增 24 小时发布窗口、前一 24 小时对照及增速；仅在覆盖明确且前窗大于零时给增速，作者/发布时间冲突、无法关联券版本时保留未知上界。


## 券月售热度指标（2026-09-28）

用户确认取消内容竞争方向，增加券月售净增速度。仅纯整数月售展示可参与计算，模糊单位和加号保持未知。速度=月售差值/间隔小时；速度变化=本段速度−上段速度；加速度=速度变化/两段时间中点间隔。至少 2 次快照可算速度，3 次可算加速度，间隔须为 1—36 小时，当前快照不超过 36 小时。仅完整品牌任务、启用品牌当前基线、同券同平台品牌归属参与，冲突品牌排除；负净增展示原值，但相关窗口不算加速度。

GET /api/v3/sales-heat 支持 brand_id、search、order=speed|acceleration|newest、filter=all|rising|accelerating|unknown、offset、limit。筛选排序在分页前执行，未知在数字之后。页面每分钟更新，展示快照原文与价格变化，沿用每日两次采集，不增加外部请求。月售口径、地域范围未被证明为真实上海新增订单，指标不称新增订单量、平台指数、内容竞争或爆款概率。本阶段作为独立热度榜，不自动改写综合评分权重。


## 2026-09-29 热度历史基准与筛选

从当前完整品牌基线向前读取最多 7 天、16 次完整快照。当前净增速度与加速度口径不变；自身历史基准排除当前窗口，只取前序连续、可比较、非负的窗口速度中位数，至少 4 个窗口且覆盖 24 小时。任一模糊销量、身份变化、负变化或采样断档中止基准累积，不跨缺口补齐。当前非负速度除以正历史基准得到相对倍数；零基准、负当前速度和不足历史均未知。此基准未校正日内/节假日或券权益变化，不声称异常显著性或爆款预测。

热度 API 新增 min_speed、min_net 和 order=lift_ratio；页面增加搜索、最低速度、最低净增数量、历史倍数排序，以及无法计算速度原因汇总。筛选在分页前执行，默认门槛 0 保留未知项，正门槛排除未知。加速度未知展示具体依据，历史记录可展开查看。


## 2026-09-29：热度结果交付

新增 GET /api/v3/sales-heat.csv，沿用热度列表的筛选和排序，但导出全部匹配结果，不使用 offset/limit 截断。UTF-8 BOM、CSV 引号转义，商品 ID 带文本标记；文本公式前缀转义，未知数值空白，负数保留。热度卡显示当前票面起价并复用现有权益/门店详情组件，不触发外部采集。后台现有分钟任务原子写入 data/reports/sales-heat-current.json 和 .csv，权限 0600；报告计算时间与样本采集时间分别保留。
