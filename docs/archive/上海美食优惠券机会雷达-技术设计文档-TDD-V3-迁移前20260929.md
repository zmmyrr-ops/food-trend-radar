# 上海美食优惠券机会雷达 技术设计文档

版本 V3.0 | 2026-09-20 | 上海 | React + Node.js

## 1 系统架构与执行边界

### 架构

React + TypeScript 负责榜单、券对比、证据和任务状态；Node.js + TypeScript 负责采集适配器、任务执行、归属校验、差异检测和纯函数评分。保留本地 PGlite 开发环境，生产建议 PostgreSQL；首版采用数据库任务队列和单一采集 Worker，无需引入分布式并发采集。

### 处理链路

Scheduler → 持久化轮次和品牌任务 → 全局串行请求门控 → DouyinSelectionAdapter → 原始响应与规范化快照 → 归属匹配 → DiffEngine → 候选补充采集 → FeatureBuilder → ScoreEngine → API 与站内提醒。先完成全量券扫描，再补充候选信号；候选补充可以跨轮继续，但必须标注各来源的观测时点。

### 定时与互斥

应用调度表达式 0 0,12 * * *，时区 Asia/Shanghai。唯一键为 source＋scheduled_at，持久化 next_run_at；数据库 lease 加 fencing token 防止多实例重复执行。没有外部 Codex 定时任务，本次文档也不代表定时采集已经启动。重启后从检查点恢复，错过多个触发只补最近一个，避免补跑洪峰。

### 全局速率门控

所有采集调用必须经过同一 dispatcher：concurrency=1；next_allowed_at = last_response_finished_at + random(1000,2000)ms。禁用 HTTP 客户端隐式自动重试，重试也排队；记录开始、结束和实际间隔。网络慢时不补偿发包，守护进程与“立即更新”共用互斥锁，不另开并发。

### 容量与任务积压

308 个品牌每品牌一页，单轮等待约 307—614 秒，另加网络和处理时间；若平均三页则约 923—1846 秒等待。这只是容量估算，不是完成 SLA。轮次超 90 分钟提醒，临近下一轮仍未完成则合并触发。不得为了赶进度增加并发或缩短间隔。

## 2 采集接口与数据准入

### 已验证查询接口

GET https://eos.douyin.com/life/alliance/v2/goods/selection/get。当前样本参数：from_type=5、sort_type=8、scene=1、city=310000、key_word=品牌词、cursor=0、count=12、image_size={"width":360}。排序及场景枚举含义未验证，先保留样本值，不能声称按最新排序。

### 成功与翻页协议

检查 HTTP 状态、JSON 解析、status_code=0 及 product_list 数组结构；分页使用返回 cursor 和 has_more，不自行递增猜测。保存请求摘要、页次、获取时间与响应摘要。重复游标、空页且 has_more=true、重复页摘要或超过单品牌 100 页上限时停止并标记 partial，不能标 complete。品牌之间按轮次固定顺序处理，失败品牌延迟重试。

### 商品字段

product_id 及 poi_id、brand_id 存字符串，避免 JavaScript 大整数精度损失；JSON 解析器必须保留超安全整数。product_info.product_name 为标题；price_range.min/max 与 origin_price 在样本中以分计，展示时除 100。origin_price=0 作为未知处理。statistics.sold_l30_count 与原始月售文案保存为平台口径的 30 天指标，不转换成当日销量。

### 门店与时间字段

nearest_poi_info.brand_data 可提供品牌 ID 和名称；poi_name、address 为关联门店信息。nearest_poi_info 只是一家关联门店，不能代替全部可用门店。city 查询参数与该门店证据一起用于上海判定，无法证明券可在上海使用则隔离。sold_start_time 保存为平台销售开始时间；product_sold_end_time 保存原文和带时区解析值，核销期限另设字段，不混用。

### 身份与权限

凭据通过首次本地配置进入受限文件或秘密存储，API 仅引用 credential_ref；禁止提交到 Git、请求日志或前端。当前验证证明会话下请求可重放，不能推断接口无需登录或长期可用。授权失效由系统暂停并提示重新登录；不设计绕过签名、验证码或风控。

## 3 存储结构与快照事务

### 品牌及采集任务

brands(id,name,aliases,enabled,category)；source_brand_bindings(brand_id,platform_brand_id,poi_ids,match_status,evidence,version)；scan_runs(id,scheduled_at,started_at,finished_at,status,coverage)；scan_tasks(run_id,brand_id,state,cursor,page_count,attempt,next_retry_at,error_code)。同一轮次与品牌唯一，保存策略版本。

### 原始页与商品快照

raw_pages(run_id,brand_id,cursor,request_hash,response_hash,storage_ref,fetched_at,status)；coupon_snapshots(id,run_id,brand_id,source_product_id,observed_at,city,price_min_fen,price_max_fen,origin_price_fen,benefits,restrictions,poi_evidence,platform_metrics,source_times,identity_confidence)。金额存整数分；缺失用 null，原始与规范化值均保留。

### 可比规格与事件

comparison_signature = 品牌＋券类型＋主权益标准项＋人数或份量＋等级＋资格＋店域＋时段及附加费规则。价格不放入规格指纹；权益变化另由可比组比较。coupon_changes(id,old_snapshot_id,new_snapshot_id,change_type,improvement,confidence,evidence,detected_at,baseline_age)。事件幂等键为品牌、旧新指纹、变化类型及规则版本。

### 信号与评分

creator_observations 保存 video_id、author_id、posted_at、observed_at、匹配券、查询策略与样本覆盖；brand_index_observations 保存 source、metric、period、value、coverage_id；environment_forecasts 保存 issued_at、valid_at、city 和预报值。score_snapshots 保存 as_of、各分项范围、上下界、完整度、gate_status、证据 ID 和 rule_version。

### 事务及基线提交

每页原始证据和规范化记录成功持久化后推进游标。所有页完成、归属及校验通过后，再以事务将品牌 run 状态置为 complete 并更新该品牌基线指针。差异生成与事件写入幂等；任务恢复可重复读页而不能重复触发告警。完整空结果只标本轮未见；连续两轮未见仍不等于证实下架。

### 保留与恢复

建议原始响应保留 30 天、快照和评分保留 12 个月，实际按平台许可调整；删除无业务用途的账号信息及带签名媒体地址。每日数据库备份、每周恢复演练；建议 RPO 24 小时、RTO 4 小时。迁移先备份，回滚服务版本不能破坏历史证据。

## 4 比价算法与特征计算

### 品牌归属

优先使用已核验 platform_brand_id，其次已核验 POI 映射；品牌名称与别名仅用于召回。标题模糊包含“牛”或“寿喜烧”不能判牛New。无准确身份匹配的商品自动进入隔离队列，覆盖报告显示未解决；不要求用户逐条确认才能让其他品牌运行。

### 可比性与改善幅度

严格可比条件：同品牌、同资格、同质量主权益、同店域或明确覆盖包含关系，限制不能变差。同规格降价 r=(old_price-new_price)/old_price，old_price 必须>0；同价同质份数增加 g=(new_qty-old_qty)/old_qty。I=100×clip(max(r,g)/0.30,0,1)，仅使用成立且有证据的分支，不将不同品类价值主观折现。限制放宽但无法量化时 I 未知，并单列事件说明。

### 价值分的其他分项

A=100×(1−同可比组单位实付价的升序百分位)，至少 5 个不同商品且来自近 30 天；样本不足为未知，不借用其他品牌不可比菜品。U 四项各 0—25：未来 7 天可用天数比例、上海适用门店覆盖比例、核销有效期 min(剩余天数/30,1)、资格与附加费透明度。资格项：无门槛且无附加费为 25，有明确限制为 10，条件未知为未知；其他未知项各保留 0—25 区间。

### 达人与指数计算

D 按 PRD 独立作者阶梯扣分；有效命中样本达到某档即可确认扣分下界，查询截断或覆盖未知时上界仍为 30。只有预定义查询组、观察窗、分页策略均成功执行才可计算样本口径的确定 D，并仍注明非全平台。H_source=0.6L+0.4G：L 为最近 7 天均值在此前 90 个完整日中的百分位，G 为本期 7 天均值相对之前 28 天均值的增幅在冻结参考分布中的百分位。历史不足或分母为零则未知。

### 环境与跨平台组合

H 固定初始权重为抖音 0.6、百度 0.2、其他一个已准入指数 0.2；缺失保留区间，不重新归一。E=clip(50+T+W+J,0,100)。T 品类温度适配范围 −20至20，W 降雨出行影响 −20至0，J 节假日需求适配 −10至20；规则按品类配置，未经验证默认中性且标注规则假设。无预报或日历数据则相应分项未知。

## 5 评分输出与接口契约

### 区间传播

所有分项使用 [lower,upper]。S_lower=clip(0.60V_lower+0.15N_lower+0.15H_lower+0.10E_lower−D_upper,0,100)，S_upper 使用各正项 upper 减 D_lower。score 只在所有必要分项确定时填数，其余为 null，返回 score_lower 与 score_upper。evidence_completeness 为所需字段的有证据权重比例，单独展示，不能称统计置信度。

### 算例与门槛

假设 V=80、N=100、H=60、E=70、D=10，则 S=69。若 D 未知，则 S 为 49—79，不得用 79 排榜或按 0 扣分。品牌归属不明、实付或主权益缺失、上海适用不明、不可售均不进入推荐榜。首次基线只展示存量，不能触发上新提醒。

### 查询 API

GET /api/v3/opportunities?view=recommended|watch&brand_id=&run_id= 返回事件、新旧券摘要、分数范围、quality_flags、各来源时点；GET /api/v3/coupons/:id/history 返回版本历史；GET /api/v3/changes/:id 返回完整差异和证据。所有 ID 为字符串，金额为整数分，时间为 ISO 8601，null 与 0 严格区分。

### 任务与设置 API

GET /api/v3/runs 和 /api/v3/runs/:id 返回进度、覆盖、失败及延迟；POST /api/v3/runs 创建受限手动任务并返回 202，Idempotency-Key 防重复；GET /api/v3/sources/health 查看会话状态。PATCH /api/v3/settings 可调整阈值、品牌启用和停采，服务端禁止并发>1或间隔<1000ms；凭据内容不返回。

### 错误及前端行为

业务错误码 AUTH_EXPIRED、RATE_LIMITED、RISK_BLOCKED、PARTIAL_SCAN、IDENTITY_UNRESOLVED、SOURCE_MISSING、STALE_BASELINE。前端以最近一次成功数据继续展示并明确标旧，不能把失败渲染为空列表或“无优惠”。券对比先显示差价与条件，再显示规则贡献及证据时间。

### 告警幂等

站内 notification 唯一键为 change_id＋alert_type＋规则版本，规则版本升级重算默认不重发。新增实质改善产生新事件；同事件分数因天气轻微波动不重复提醒。来源故障单独告警，不与选题推荐混排。外部通知不在首版自动开启。

## 6 容错部署与开发验收

### 错误处理

401/403、身份失效或风险提示立即暂停相关来源，不自动反复登录。429 按 Retry-After 等待，缺失时退避 60秒、5分钟、30分钟；最多 3 次，仍失败暂停来源。网络超时或 5xx 最多 3 次，退避 30秒、2分钟、10分钟。所有重试仍遵守串行门控，其他来源可在其允许时段继续执行。

### 监控与非功能要求

记录在途请求数、请求间隔、限流率、业务错误、品牌任务覆盖率、partial 比例、身份匹配率、基线年龄、各信号时延和提醒重复率。推荐榜数据通常使用最近完整轮次；旧于 24 小时标过期。目标缓存查询 P95<500ms，开发机至少支持 308 品牌及 90 天回放；容量验收按实测页数报告。

### 部署与秘密管理

单实例 Node Worker 与 API、React 静态服务、PostgreSQL 部署在受控环境。开发用 PGlite 时仅一个进程拥有写连接。配置使用 credential_ref、TZ、rule_version、page_limit、timeouts 和 retention_days，秘密由环境秘密挂载，文件权限 0600。停采开关持久化，升级前停止领取任务，完成当前请求后保存检查点。

### 里程碑顺序

M1 实现真实券采集、串行节奏、两次日调度和快照；M2 实现精准归属、新旧对比及观察榜；M3 完成达人样本、指数和天气日历准入与分项计算；M4 上线完整机会榜、提醒及全品牌 7 天试运行。M1 和 M2 不因外部指数缺失停工，M3 未通过的来源保持缺失。

### 验证与校准

单测覆盖金额精度、大整数 ID、首次基线、套餐不可比、缺失区间、风险暂停及幂等。集成测试使用脱敏固定响应验证跨页去重、重启恢复、事务回滚、两轮差异和单 Worker 互斥。实时试点采用多品类约 10 品牌后扩全池，依然串行。评分回测只使用 available_at≤as_of 的证据，天气用当时预报；训练与评估按时间划分并隔离同券事件，防泄漏。

### 依赖与迁移说明

Node.js 规则计算可独立闭环，大模型不是运行必需；可选文本抽取必须返回字段证据与失败状态。旧的 6 小时公告调度与旧榜单从主流程停用，历史记录只读保留。当前只完成新版文档和 TODO 更新，生产调度、适配器与评分实现均以 TODO 验收为准。

## 2026-09-28：未来 72 小时使用限制落地

基于当前品牌完整轮次的价格与规则证据，以 Asia/Shanghai 日期切分滚动 72 小时（非午夜通常跨 4 个日历日），识别完整、无例外的明确禁用日期、日期区间、星期和命名节假日。未识别的日期条款保留原文，泛称法定节假日不自动映射为全部放假日期；2026 年以外命名节假日保持未知。时段保留秒与跨夜标记，只展示条款，不推断门店营业时间。

价格须在当前 36 小时内，规则须不早于价格且不晚于当前时间；缺失和过期不借用旧规则。购买后有效天数不从采集时刻起算。输出仅有明确禁用或未确认，不输出已确认可用，也不提高环境分或完整权益等级。

新增 GET /api/v3/coupons/:id/use-outlook?brand_id=UUID；机会榜、跨券匹配和当前规则 API 携带 use_outlook，简报带禁用日期。机会榜支持 usage=any|has_exclusions|not_fully_excluded，在分页前筛选。全部基于已落库数据计算，无额外平台请求。


## 2026-09-28：达人搜索准备与准入边界

GET /api/v3/creator-search（可选 brand_id）直接使用当前机会榜候选，按品牌、券名、固定成交价生成检索方案，方案随券 revision 变化；暂不考虑与历史再现不进入计划。范围价不冒充唯一成交价。此接口不触发外部采集，automatic_collection=false，状态 blocked_source，真实人数与视频数为 null，扣分保留 0—30。网页检索链接用于来源验证，不要求用户日常人工录入。

当前尚无真实搜索样本。官方文档提供视频 ID、发布时间、昵称与点赞示例；作者稳定 ID 和具体券版本关联尚未验证，不可用昵称去重。搜索分页结束不等于平台全部视频覆盖。统计算法新增 24 小时发布窗口、前一 24 小时对照及增速；仅在覆盖明确且前窗大于零时给增速，作者/发布时间冲突、无法关联券版本时保留未知上界。


## 券月售热度指标（2026-09-28）

用户确认取消内容竞争方向，增加券月售净增速度。仅纯整数月售展示可参与计算，模糊单位和加号保持未知。速度=月售差值/间隔小时；速度变化=本段速度−上段速度；加速度=速度变化/两段时间中点间隔。至少 2 次快照可算速度，3 次可算加速度，间隔须为 1—36 小时，当前快照不超过 36 小时。仅完整品牌任务、启用品牌当前基线、同券同平台品牌归属参与，冲突品牌排除；负净增展示原值，但相关窗口不算加速度。

GET /api/v3/sales-heat 支持 brand_id、search、order=speed|acceleration|newest、filter=all|rising|accelerating|unknown、offset、limit。筛选排序在分页前执行，未知在数字之后。页面每分钟更新，展示快照原文与价格变化，沿用每日两次采集，不增加外部请求。月售口径、地域范围未被证明为真实上海新增订单，指标不称新增订单量、平台指数、内容竞争或爆款概率。本阶段作为独立热度榜，不自动改写综合评分权重。


## 2026-09-29 热度历史基准与筛选

从当前完整品牌基线向前读取最多 7 天、16 次完整快照。当前净增速度与加速度口径不变；自身历史基准排除当前窗口，只取前序连续、可比较、非负的窗口速度中位数，至少 4 个窗口且覆盖 24 小时。任一模糊销量、身份变化、负变化或采样断档中止基准累积，不跨缺口补齐。当前非负速度除以正历史基准得到相对倍数；零基准、负当前速度和不足历史均未知。此基准未校正日内/节假日或券权益变化，不声称异常显著性或爆款预测。

热度 API 新增 min_speed、min_net 和 order=lift_ratio；页面增加搜索、最低速度、最低净增数量、历史倍数排序，以及无法计算速度原因汇总。筛选在分页前执行，默认门槛 0 保留未知项，正门槛排除未知。加速度未知展示具体依据，历史记录可展开查看。
