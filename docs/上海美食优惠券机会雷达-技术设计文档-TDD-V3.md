# 上海美食优惠券热度雷达 · TDD V4

更新：2026-09-29。现行实现为 React + TypeScript + Node.js/Express + PGlite，单机单进程；文件名保留旧版本号以兼容链接。

## 1. 架构与部署

React 页面 → 本机 Express API → PGlite 持久层。后台调度、平台串行门控、列表采集、规则/门店补采、热度读取、证据记录和报告共用服务进程。没有分布式队列、高可用或大模型依赖。

macOS launchd 登录会话常驻，运行副本位于 ~/Library/Application Support/food-trend-radar/runtime，唯一数据位于相邻 data。源码 data 为链接。同库进程用本机互斥保护；禁止脚本另开活动数据库。休眠和关机不执行采集。

部署流程：npm run check → 暂停采集 → local-service stop → 确认进程及数据库锁释放 → prepare-local-runtime → local-service install → 恢复采集并检查 API。不要同时 npm run dev。

## 2. 采集、调度与容错

上海 00:00/12:00 时段去重，重启仅补当前时段。所有平台请求共用单请求门控，响应后 1000—2000ms 等待。列表每五成功页穿插规则/门店，余下补采继续轮换。

分页检查点、商品幂等写入、品牌完整任务提交基线。鉴权/限流/业务结构异常暂停；网络及部分 5xx 限次退避。部分失败不更新基线，过期或查询口径变化重建。真实 HTTP 成功不代表业务完整，门店数量不符及字段缺失分别记录。

## 3. 数据模型与字段

brands 保存本地品牌与别名；coupon_runs/tasks 保存轮次和品牌状态；coupon_items 保存每轮商品 payload、时间；coupon_baselines 指向完整任务；coupon_diffs 保存差异；rule/store tasks 与 snapshots 保存补采及证据；coupon_score_history/checks 保存版本化评估和轮转进度；radar_alerts 保存站内提醒。

商品 ID 始终字符串，金额整数分；月售 monthly_sales 保存原始展示。平台品牌 ID 与本地品牌关系做冲突隔离。current/previous 规则和门店按轮次关联，不能借用别轮证据。

## 4. 特征工程与版本

sales-heat.ts 从当前启用品牌完整基线取同品牌同券历史（七天/16 点），排除归属冲突。整数解析、1—36 小时间隔、36 小时新鲜度；速度、加速度和历史倍数公式见 PRD。返回 samples、net_change、hours、speed、previous_speed、acceleration、baseline_speed、lift_ratio、reason 等，未知为 null。

历史按完整品牌任务展开，左连接商品，未见券保留缺失节点；缺失节点不作为零销量，不能跨节点比较。查询签名与券名变化也截断对应窗口。标题不变的实际套餐变更仍待核验。统计窗口/地域尚未验证，输出名保持“月售展示净变化”，不能当上海新增订单。

score-history.ts 分批计算 V4.2.sales-evidence，features.sales_heat 存真实指标及样本，evidence 存权益比较。payload 哈希形成版本，无变化不重复写。每批默认 100，证据更新优先兼顾普通券；发布后逐批迁移，不承诺瞬间全部刷新。

score_status=not_calibrated、gate=watch、alert=false。range 为兼容旧内部结构的未知占位，不是可展示分数；页面 V4 不显示区间。旧 V3 纯函数和历史保留，当前调用链移除达人因子。score-evidence-sql 只允许 V4 且当前证据匹配的记录进入当前列表。历史 API 保留旧版并标明版本。

没有已训练模型或推理服务；当前是确定性计算。未来训练需先取得结果标签、按时间切分并防未来信息泄漏，再校准和独立验证。

## 5. API 与页面

- GET /api/v3/sales-heat：品牌/关键词/filter/order/min_speed/min_net/offset/limit；过滤后分页。
- GET /api/v3/sales-heat.csv：相同筛选排序，导出所有匹配项；长 ID 文本标记、防公式前缀、null 留空。
- GET /api/v3/coupons/:id/scores?brand_id=UUID：版本化历史及 current_version。
- GET /api/v3/rankings：当前已完成 V4 评估且证据匹配的子集，按速度排序；完整实时结果使用 sales-heat。
- GET /api/v3/selection-brief 与 .md：全池热度摘要、Top 10、优惠线索及跨券比价；不跟随页面临时筛选。
- GET /api/v3/operations、/stability、/alerts：运行、14 时段验收、历史提醒；POST /alerts/:id/ack 标已读。
- PATCH /api/v3/settings：现有服务开关/暂停。达人搜索路由不再注册。

页面每分钟刷新本地数据。规则和门店按钮读取已落库证据，不直接触发并发平台请求。参数以实际 zod schema 为准。

## 6. 报告、监控与合规

后台每分钟原子保存 sales-heat-current.json/.csv、selection-brief-current.json/.md、stability-current.json。数据报告权限 0600。请求审计统计开始/结束/间隔/结果；稳定性仅验收已结束自然时段，手动扫描不抵扣。

凭据本地 secrets/douyin-headers.json，固定 eos.douyin.com 接收，禁止日志/前端输出，不纳入备份。接口仅本机、带来源限制，无公网租户权限体系。遵守用户授权范围，失败暂停；不能承诺账户风险为零。天气许可需在商用前核验。

每日一致性备份保留七份，可通过 verify-backup.mjs 在独立库恢复验证。启动故障不得并行打开主库。队列积压、门店范围和统计口径缺失不因系统健康而自动视为成功。

## 7. 开发验收

npm run check 覆盖格式、类型、API 测试和生产构建。V4 回归关注真实速度落入证据、缺失不补零、旧版不进当前排序、重复证据不重复落库、不触发旧推荐、简报包含热度。发布后通过实际本机接口复核。

## 来源留证与补采诊断（2026-09-29）

规范化时在 source_evidence.sales 保存 product_info.sold_count_display 原文和有限销量计数字段清单。只接受受限名称、长度及原始标量，不保存整个响应或请求头。该清单只用于字段核验，不参与精确销量替代；原有 monthly_sales 仍取展示字段。

GET /api/v3/source-diagnostics 提供当前启用品牌的留证覆盖、已观察字段计数、明确未知的统计定义，及当前新鲜基线补采状态、退避数、重试数和近 24 小时分类型请求结果。旧快照没有字段清单，不反推接口不存在精确字段。该接口只读本地库，不增加平台请求。

规则与门店入队仅允许启用品牌；停用品牌排队任务退出。网络最多两次重试，任务重试预算落库，重建 worker 不重置。达到上限的本轮任务不自动无限补跑；新完整基线重新建立新轮次任务。门店任务包含多批，排队任务数不能换算成剩余请求数或确定完成时间。

## 补采任务轮换（2026-09-29）

规则/门店任务增加 last_attempt_at。进入共享门控且未暂停后、发起请求前记录请求时间。选择任务先区分退避未到期与可执行任务，再应用原优惠优先级，最后按上次请求时间最早（未尝试优先）轮转。每四次普通轮转仍保留，普通任务不会永远被优惠优先任务挤占。所有任务都退避时仍交由共享门控等待截止时间，不忙循环、不提前重试。

门店按 20 ID 一批，每批后让出同级任务机会，游标仍落库，不重复已查询批次。重启保留请求时间和游标。此调整改善机会分配，不增加总请求吞吐，不承诺立即清空积压；大任务完整结果可能更晚取得。

### 同名券权益连续性（2026-09-29）

V4.2 将各样本所属轮次的规则快照与月售记录关联。两端规则完整、指纹非空、规则在列表采集之后 36 小时内取得，且上轮详情不晚于下轮列表时，才比较套餐/条款指纹。返回内容不同则阻断相应速度、加速度或历史基准窗口。

证据不足时，月售展示净变化仍可独立计算，但 content_comparison=unknown，不宣称同权益连续增长；same_returned_content 仅表示已返回信息相同，不代表完整权益核验。页面及 CSV 均展示该区别。指纹变化也可能来自条款或列示顺序调整，当前保守截断，不推断销量重置。真实平台统计定义仍待确认。

## 跨时段串行排队（2026-09-29）

新 00:00/12:00 时段建立独立轮次，即使上一轮尚未完成；唯一 slot 防重复。单个 worker 按轮次创建时间和 ID 顺序执行，共用原全局串行门控。手动触发仍合并进最早运行轮次。排队轮次沿用 running 状态表示尚未结束，不表示同时发请求。

schedule 去重后仍调用 kick，使重启/暂停后已存在的排队任务能够恢复；完全完成轮次不重复采集。休眠期间仍只补当前时段，不凭空回补历史数据。排队不保证在本时段完成，原七天验收器仍按实际完成时间判迟到。

## 数值独立复算（2026-09-29）

sales-heat-audit.ts 独立解析样本原始月售展示，不调用 salesTrend，也不使用其 parsed_value。对已发布的净增、间隔、速度、窗口中点加速度、历史中位数和倍数逐项复算，容差为 1e-8 × max(1,|期望值|)，拒绝非法/无限数值。未知不参与“通过”样本计数。

后台报告循环使用同一组 heatRows 原子保存 sales-heat-audit-current.json（0600），输出覆盖计数和字段级误差；不增加平台请求。该报告验证算术一致性，不能代替平台统计定义、品牌归属、权益连续性或模型准确率验收。
