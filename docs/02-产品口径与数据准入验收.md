# 02 产品口径与数据准入：实现与验收记录

本章软件实现与业务验收分别记录。更新时间：2026-09-20。范围为上海、目标200个独立品牌、最低150个。

## 本轮交付

打开工作台「产品与准入」。它读取真实本地数据库，展示品牌数量、按品类建议配额计算的缺口、品牌名与别名冲突候选、来源门禁原因、200品牌调用量与预算估算。未生成虚构品牌、账户实测或连续日报。

口径配置在 packages/contracts/src/admission.ts，版本 shanghai-l1-v1。配置摘要采用稳定排序JSON的SHA-256；评审写入摘要、配置快照、核验人、说明和服务器时间。代码版本变化不会让旧评审自动认可新配置。该评审是本地自填记录，不是认证账号签名。

## 逐项验收状态

- DATA-GATE-01：实测登记功能完成；真实账户调用验收未完成。登记脱敏账户标识、平台、接口、三项指标字段和单位、覆盖口径、用途许可、证据链接及摘要、观测时间、轮次与预算。不接收密钥，不自动访问提交的链接。来源配置变更使旧实测失效。
- DATA-GATE-02：7日报检查完成；真实连续7天运行未完成。只接受实测登记日至昨天的完整上海自然日，不能回填登记前日期。一来源实测版本一天一份报告，10—20个已核验品牌、至少3品类、7天保持同一集合。需每天达到计划调用量、成功率和完整率≥95%、重复率≤5%、最大延迟≤360分钟。门槛为工程初值，不是已证实的平台SLA。
- DATA-GATE-03：未达门禁时p72与抢跑指数为null，正式发布关闭。单独定义editorial-v1观察分，官方72小时新品35、公开优惠30、上海参与20、视觉新鲜度15；必须逐项有证据，任一未知不评分。没有沿用原八因子权重，也不启用观察分告警。本章仅定义规则，不提前实现第07章评分引擎。
- SPEC-01：建库工具、核验、关键词、统计与冲突候选完成；150—200个真实独立品牌及上海证据验收未完成。别名冲突是人工复核线索，不自动合并，也不据此宣称实体去重全部完成。
- SPEC-02：监测单位固定为brand_id、event_id、310000、as_of。事件准入响应提供服务器当前时点的单位信息；正式特征和预测快照持久化属于后续章节，未实现时不制造预测历史。
- SPEC-03：全国活动通过具体上海门店名、地址、地域310000、证据链接、参与条件、价格及核验有效期建立映射。可参与至少需要一个上海门店证据，不意味着所有上海门店适用。事件更正、核验过期均重新待核验。未知不作为可参与；优惠推荐还需后续价格真实性验证。
- SPEC-04：官方权限资料已复核，但尚无可确认满足本项目需求、内容数、作者数三项指标的合法账户级渠道，保持未完成。
- SPEC-05：全量、授权样本、人工样本分别登记。当前L1-v1采用上海全量小时口径；授权样本和全国信号仅用于另外定义、另行验证的版本，不能静默替代。本版使用同一来源覆盖三项核心指标，跨来源对齐属于后续扩展。
- SPEC-06：时间粒度、延迟、配额、成本及200品牌负载字段和门禁完成。实际来源值未实测，不能宣称完成数据源能力验收。
- SPEC-07：来源主体、用途、期限、展示/训练权限、保留期登记已完成。实际保留期自动删除任务属于后续运维章节。
- SPEC-08：新品、联名、优惠、开店、节日限定五类通过前后端共享枚举限制；错误枚举被拒绝。
- SPEC-09：食品安全、负面舆情、虚假优惠、缺货、未知风险均不能成为无风险本地候选，不自动推荐。风险核验仅人工事实登记，不用未证实传闻作事实；解除需新证据和追加核验记录。负面事件不因传播热度变高而转为拍摄推荐。
- SPEC-10：界面明确规则观察、选题观察分、正式概率及抢跑指数；未校准显示未知，分数禁止百分号。当前模型未验收，任何许可或评审记录均不能开启预测。
- SPEC-11：标签、权重、告警初版参数、版本摘要与人工评审记录完成；饱和度所需头部阈值和参考分布没有真实训练样本，保持未就绪，最终评审冻结未完成。不得将默认数值伪装成数据校准参数。

## 7天与200品牌成本验算

单日调用预算=200×每品牌词数×每词页数×每日轮次×1.2，向上取整；1.2为重试预留。小时计划每日至少24轮。例：3词×3页×24轮需51840次/日（含重试），不能用1000次/日配额宣称通过。

预计月成本=7日平均的「每日增量成本×200/试点品牌数」×30×1.2+固定月费。日报成本不含固定月费，避免重复计算。阶梯计费、分页差异等非线性成本需在实测备注中另行核对，本估算不是报价。缺配额、延迟或月费视为未知，不填0冒充可用。

数据门禁passed仅表示录入证据符合规则，系统不能仅靠链接和摘要鉴定证据真实性。最终真实账户验收仍由运营对照脱敏响应完成。即使数据门禁通过，模型、标签阈值和独立回测未验收时，正式发布仍为false。

## 接口与记录

- GET /v1/admission：产品口径、品牌缺口、来源门禁、发布限制。
- POST /v1/admission/review：当前配置摘要的人工评审；保存版本快照。
- GET/POST /v1/admission/audits：不可覆盖的账户实测记录。
- GET/POST /v1/admission/trials：不可覆盖的按日验证记录；重复日拒绝写入。
- GET/POST /v1/events/:id/admission：上海门店映射与风险核验，保留历次记录。

旧品牌、事件、来源数据经数据库迁移v4保留。证据链接仅保存引用，未提供对象存储或文件摘要自动比对。纠错通过新的实测批次开始，避免覆盖已经参加验收的历史日报。

## 软件验证与业务限制

自动化测试使用隔离数据库、明确测试数据，覆盖来源口径不兼容、配置失效、7日缺测、品牌集合变化、预算/配额不足、风险类型拦截、事件修改后证据失效、过期版本评审拒绝及概率始终为空。测试通过不替代真实7天运行。

尚需实际资源：合法的数据提供方和账户权限、150—200个品牌可核验上海证据、真实脱敏调用响应、连续7个完整自然日记录。没有这些资源，本章节不能诚实标注“全部业务验收通过”。系统保持可运行的人工工作台与未通过原因，不伪造外部数据。
