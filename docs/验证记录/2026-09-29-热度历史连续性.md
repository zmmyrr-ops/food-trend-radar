# 月售热度历史连续性修复

日期：2026-09-29。对应 TODO P1-3a；本机已部署 V4.1.sales-evidence，并恢复采集。

## 问题与修复

原查询只读取存在商品记录的历史，会跳过中间完整品牌扫描未见券的轮次。现改为按完整品牌任务展开，左连接商品；缺券保留 missing 节点、轮次及任务完成时间，不补零，不认定下架。

相邻节点缺失时不计算该段速度；加速度和历史基准也在缺口处截断。未完成的扫描不当作缺券。查询签名不一致、品牌归属不一致或券名变化，同样停止对应窗口比较。单纯价格变化仍可计算展示销量，但单独说明价格变化。

评估版本升级 V4.1，旧版证据不再进入当前排序；历史保留。热度页面在样本中标注完整扫描未见。新评估按批更新。

## 验证

完整检查通过：113 项测试、零失败，类型检查及生产构建通过。新增数据库集成测试覆盖当前缺口、较早缺口导致加速度/基准中断、普通连续历史、未完成任务排除、查询范围和券名变化；沿用品牌归属及负净增保护测试。

生产只通过本机 API 读取，未另开主库、未新增批量平台请求。上线实测 3100 张券、787 张可算速度、294 张净增长；541 张当前窗口遇到缺券节点，297 张券名变化保持未知；当前排名仅 V4.1。一次热度接口实测约 331ms（不代表性能保证）。详情见同名 JSON。

服务启用、无暂停原因，并发 1、请求完成后等待 1000—2000ms。

## 未验收边界

券名变化可能只是营销文案，当前保守暂停比较；券名不变也不保证套餐未改变，实际权益变更仍列 P1-3b。月售统计窗口、地域、退款和重置口径尚未确认。没有伪造真实加速度/历史倍数样本。
