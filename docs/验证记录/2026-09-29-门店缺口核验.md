# 门店补采缺口核验

## 本次实现

继续 P1-4b：在已有来源诊断中加入门店范围核验，并接入运行状态页面和每分钟自动报告 `data/reports/source-diagnostics-current.json`。仅查询本地当前活跃品牌的新鲜完整基线，不新增平台请求，不改变串行门控、重试预算或门店保护上限。

区分等待范围、等待剩余门店查询、平台返回 ID 少于声明总数、已查询后部分 ID 未返回、空范围、超过 1000 个 ID 上限、计数矛盾、已停止但未查完、缺少最终快照、请求终止与完整核对。每类最多展示 3 张真实券，包含品牌、券 ID、轮次、声明数量、返回 ID 数、已查询数、最终取得数及快照时间。

平台声明总数与返回 ID 差额、查询后未返回差额分别计算。按券累计，可能重复涉及同一门店，不当成缺失门店去重数。不因 ID 列表已查完就把缺少范围的券标成完整，也不把未查完任务认定为平台漏数据。

## 验证范围

测试覆盖来源差额、查询差额、未开始、未完成、空范围、上限、计数/状态矛盾、快照缺失、当前基线过滤、停用品牌排除及聚合样本追溯。不会把最终失败任务无限重新入队。

真实统计与案例在部署后从本机诊断 API 获取，保存同目录部署 JSON。补采队列尚未全部消化，来源数量不一致的业务原因尚未核实，P1-4b 不整体勾选完成。

## 部署实测

131 项测试和完整检查通过。诊断查询耗时见部署 JSON，恢复采集后的统计共 3116 张券：2485 张待取门店范围、25 张待继续查询、304 张 ID 返回范围少于声明总数、302 张返回范围已完整核对。

真实来源缺口案例：1 点点券 1784360500535328 声明 5339 / 返回 50 / 查询 50 / 取得 50；CoCo都可券 1781886373728308 为 2755 / 50 / 50 / 50；Lavazza 券 1787671885915156 为 203 / 50 / 50 / 50。三例均不是取得 ID 后查询漏项；这里只证明已存响应的数量差异，不证明平台固定上限，也未验证如何获得剩余范围。不能据此宣称覆盖上海所有门店。

部署后已恢复串行采集，未增加额外采集请求。实时统计会随新基线与补采变化，以上是本次核验截面。
